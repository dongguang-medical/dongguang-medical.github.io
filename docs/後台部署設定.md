# 後台部署設定（網站管理者技術文件）

本文件說明如何把 `admin/`（Sveltia CMS）後台正式啟用。後台程式本身是純靜態頁面，
隨 GitHub Pages 一起發佈即可，**唯一需要額外架設的是 GitHub OAuth 登入代理**。

- 後台網址：`https://dongguang-medical.github.io/admin/`
- 後台設定檔：`admin/config.yml`
- CMS：[Sveltia CMS](https://github.com/sveltia/sveltia-cms)（相容 Decap CMS 設定格式）

---

## 1. 為什麼需要 OAuth 代理

Sveltia CMS 透過 GitHub OAuth 讓店員登入並讀寫 repo。OAuth 的 token 交換必須有一個
伺服器端元件保管 client secret，GitHub Pages 是純靜態託管無法承擔此角色，因此需要
架一個極小的代理服務。官方提供現成的 Cloudflare Workers 版本（免費方案即可，流量
遠低於免費額度）：

- 官方代理專案：**[sveltia/sveltia-cms-auth](https://github.com/sveltia/sveltia-cms-auth)**
- 部署步驟以該專案 README 為準（有一鍵 Deploy 按鈕，也可 clone 後用 `wrangler deploy`）

## 2. 部署步驟總覽

### 2.1 部署 Cloudflare Worker

1. 註冊/登入 Cloudflare（免費方案即可）。
2. 依 [sveltia-cms-auth README](https://github.com/sveltia/sveltia-cms-auth#readme) 部署 Worker
   （README 頂部有「Deploy to Cloudflare Workers」按鈕）。
3. 部署完成後記下 Worker 網址，格式為：

   ```
   https://sveltia-cms-auth.<你的子網域>.workers.dev
   ```

### 2.2 建立 GitHub OAuth App

1. 到 <https://github.com/settings/applications/new>（建議用管理者/組織帳號建立）。
2. 填寫：
   - **Application name**：例如 `Dongguang CMS`
   - **Homepage URL**：`https://dongguang-medical.github.io`
   - **Authorization callback URL**：`<Worker 網址>/callback`
     例如 `https://sveltia-cms-auth.xxx.workers.dev/callback`
3. 建立後取得 **Client ID**，並產生一組 **Client Secret**。

### 2.3 設定 Worker 環境變數

在 Cloudflare 儀表板該 Worker 的 **Settings → Variables** 加入：

| 變數名稱 | 值 | 備註 |
|---|---|---|
| `GITHUB_CLIENT_ID` | OAuth App 的 Client ID | 明文即可 |
| `GITHUB_CLIENT_SECRET` | OAuth App 的 Client Secret | 務必點 **Encrypt** |
| `ALLOWED_DOMAINS` | `dongguang-medical.github.io` | 選填但強烈建議，限制只有本站能使用此代理 |
| `GITHUB_HOSTNAME` | （不用設） | 預設 `github.com` |

設定後重新部署（或儲存時自動套用）。

### 2.4 回填 `admin/config.yml` 的 `base_url`

`admin/config.yml` 目前的 backend 區塊是：

```yaml
backend:
  name: github
  repo: dongguang-medical/dongguang-medical.github.io
  branch: main
  base_url: https://REPLACE-WITH-OAUTH-WORKER.workers.dev   # ← placeholder
```

把 `base_url` 換成 2.1 取得的實際 Worker 網址（**只填根網址，不含 `/callback`**）：

```yaml
  base_url: https://sveltia-cms-auth.<你的子網域>.workers.dev
```

改完發佈到 `main` 後，後台登入即可運作。

## 3. 幫店員開通帳號

1. 幫店員申請一個 GitHub 帳號（或請店員自己註冊），記下帳號名稱。
2. 到 repo 的 **Settings → Collaborators and teams → Add people**，
   輸入店員的 GitHub 帳號，權限選 **Write**（需要能推送內容到 `main`）。
3. 店員的信箱會收到邀請信，請店員點信中的接受連結。
4. 店員第一次登入後台時，GitHub 會跳出 OAuth 授權畫面，按 **Authorize** 即完成。

> 若不想讓店員自己管理 GitHub 密碼，也可以由管理者代管一個專用帳號
> （例如 `dongguang-staff`），把帳密交給店員使用。

## 4. 內容契約（與前台共用）

後台寫入的商品資料格式如下，前台建置流程需與此一致：

- 商品檔：`content/products/*.md`（YAML frontmatter + Markdown 內文）
- 檔名：`YYYYMMDD-<短ID>.md`（slug 樣板 `{{year}}{{month}}{{day}}-{{uuid_short}}`，避免中文檔名）
- 欄位：`name`（必填）、`category`（必填，四選一）、`subcategory`、`price`、`brand`、
  `tags`（字串清單）、`specs`（`label`/`value` 物件清單）、`images`（圖片路徑清單，
  第一張為封面）、`published`（布林，預設 `true`）、內文為商品說明
- 圖片實體存放：`assets/uploads/`；frontmatter 中引用路徑：`/assets/uploads/...`

## 5. 其他備註

- **編輯預覽已關閉**（`editor.preview: false`）：本站沒有 CMS 預覽樣板，關閉以保持
  介面極簡。若日後想開啟，把該設定改為 `true` 即可。
- **UI 語言**：Sveltia CMS 介面語言跟隨瀏覽器語言自動切換；所有欄位標籤與提示
  已在 `config.yml` 中設為繁體中文。
- **發佈延遲**：儲存後由 GitHub Pages 重新建置，一般 1～3 分鐘生效，已在店員說明
  文件中註明。
- **CDN**：`admin/index.html` 由 unpkg 載入 `@sveltia/cms` 最新版；如 unpkg 不穩，
  可改用 jsDelivr：`https://cdn.jsdelivr.net/npm/@sveltia/cms/dist/sveltia-cms.js`。
- **安全**：Client Secret 只存在 Cloudflare Worker 的加密環境變數中，絕不可寫進
  repo；`ALLOWED_DOMAINS` 請務必設定以防代理被他站盜用。
