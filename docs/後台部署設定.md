# 後台部署設定（網站管理者技術文件）

本文件說明如何啟用 `admin/`（Sveltia CMS）後台的 GitHub 登入。後台程式本身是純靜態
頁面，隨 GitHub Pages 一起發佈即可，唯一需要額外架設的是 **GitHub OAuth 登入代理**。

- 後台網址：`https://dongguang-medical.github.io/admin/`
- 後台設定檔：`admin/config.yml`
- CMS：[Sveltia CMS](https://github.com/sveltia/sveltia-cms)（相容 Decap CMS 設定格式）

> **目前狀態：已完成部署**，本文件可作為日後重建或轉移時的參考。
> 現行 Worker 網址：`https://sveltia-cms-auth.zirulin810.workers.dev`

---

## 1. 為什麼需要 OAuth 代理

Sveltia CMS 透過 GitHub OAuth 讓店員登入並讀寫 repo。OAuth 的 token 交換必須由
伺服器端保管 client secret，GitHub Pages 是純靜態託管無法承擔這個角色，因此需要
架一個極小的代理服務。官方提供現成的 Cloudflare Workers 版本，免費方案即可，
流量遠低於免費額度。

官方代理專案：**[sveltia/sveltia-cms-auth](https://github.com/sveltia/sveltia-cms-auth)**

## 2. 部署步驟

### 2.1 部署 Cloudflare Worker

1. 註冊或登入 [Cloudflare](https://dash.cloudflare.com)（免費方案即可）
2. 打開 [sveltia-cms-auth](https://github.com/sveltia/sveltia-cms-auth#readme)，
   點 README 頂部的 **Deploy to Cloudflare Workers** 按鈕
3. 依畫面指示登入 Cloudflare 並完成部署

> **這一步會在你的 GitHub 帳號下建立一個新的 repo**（名稱通常是 `sveltia-cms-auth`）。
> 這是正常的：Cloudflare 會把 Worker 的原始碼複製一份到你的帳號，並接上自動部署，
> 之後 Worker 有更新都從那個 repo 走。**不要刪除它。**

### 2.2 找出 Worker 網址

這個網址**不存在於任何現成的地方，是部署當下才產生的**，所以在專案裡怎麼找都找不到。

1. 進入 [Cloudflare 儀表板](https://dash.cloudflare.com)
2. 左側選 **Workers & Pages**（新版介面在 **Compute → Workers**）
3. 點清單中的 **`sveltia-cms-auth`**
4. 網址顯示在頁面上方，格式為：

   ```
   https://sveltia-cms-auth.<你的Cloudflare子網域>.workers.dev
   ```

   本站目前是 `https://sveltia-cms-auth.zirulin810.workers.dev`

若在 Cloudflare 找不到這個 Worker，代表部署沒有真的完成（可能只建了 repo）。
到 2.1 建立的那個 repo 看 **Actions** 分頁是否有失敗的部署，或重跑一次 Deploy 按鈕。

### 2.3 建立 GitHub OAuth App

1. 開 <https://github.com/settings/applications/new>
2. 填三個欄位：

   | 欄位 | 內容 |
   |---|---|
   | Application name | `Dongguang CMS` |
   | Homepage URL | `https://dongguang-medical.github.io` |
   | Authorization callback URL | `<2.2 的網址>/callback` |

   callback 範例：`https://sveltia-cms-auth.zirulin810.workers.dev/callback`

3. 按 **Register application**，記下 **Client ID**
4. 按 **Generate a new client secret**，立刻複製。**這串只會顯示一次**

### 2.4 設定 Worker 環境變數

回到 Cloudflare 該 Worker 的 **Settings → Variables and Secrets**，加入：

| 變數名稱 | 值 | 類型 |
|---|---|---|
| `GITHUB_CLIENT_ID` | 2.3 的 Client ID | Text |
| `GITHUB_CLIENT_SECRET` | 2.3 的 Client Secret | **Secret（要加密）** |
| `ALLOWED_DOMAINS` | `dongguang-medical.github.io` | Text |

存檔後會自動重新部署。

`ALLOWED_DOMAINS` 雖然是選填，但**請務必設定**，否則任何人都能拿你的 Worker
當作自己網站的 OAuth 代理。

### 2.5 回填 `admin/config.yml`

```yaml
backend:
  name: github
  repo: dongguang-medical/dongguang-medical.github.io
  branch: main
  base_url: https://sveltia-cms-auth.zirulin810.workers.dev
```

兩個重點：

- `base_url` **只填根網址**，不要帶 `/callback`，也不要加結尾斜線
- `repo` 必須與實際的 repo 路徑一致。本 repo 曾由 `dongguang-medical/website`
  搬遷為 `dongguang-medical.github.io`，設定檔一度沒跟著更新，這種情況即使
  OAuth 接好也會連到不存在的位置

改完推送到 `main`，等 GitHub Pages 重建（約 1 到 3 分鐘）即可使用。

### 2.6 驗證是否成功

不必等到實際登入，用指令就能確認 Worker 與環境變數是否就緒：

```bash
curl -s -i "https://sveltia-cms-auth.zirulin810.workers.dev/auth?provider=github&site_id=dongguang-medical.github.io" | head -5
```

**正常回應**長這樣：

```
HTTP/2 302
location: https://github.com/login/oauth/authorize?client_id=Ov23li...&scope=repo%2Cuser&state=...
```

看到 `302` 且 `location` 指向 GitHub、帶著你的 `client_id`，就代表 Worker 已上線且
`GITHUB_CLIENT_ID` 設定正確。

其他情況：

| 現象 | 意義 |
|---|---|
| 根路徑 `/` 回 404 | **正常**，這個 Worker 只處理 `/auth` 與 `/callback` |
| `/auth` 回 500 或錯誤訊息 | 環境變數沒設好，回 2.4 檢查 |
| 完全連不上 | Worker 沒部署成功，回 2.1 |

## 3. 第一次登入會看到什麼

點 **Sign in with GitHub** 後，GitHub 會跳出授權確認畫面，各區塊的意思：

**權限範圍**

| 項目 | 意義 |
|---|---|
| Repositories：Public and private | 取得你所有 repo 的讀寫權，包含私有的 |
| Personal user data：Full access | 讀取帳號資訊，後台用來顯示登入者 |

這對應 Sveltia CMS 要求的 `repo,user` 權限。範圍比實際需要的大：後台其實只需要寫
一個 repo，但傳統 OAuth App 無法限定到單一 repo，只能全給或全不給，這是 GitHub 的
機制限制。因為 App 與 Worker 都是自己建的、Client Secret 只存在自己的 Cloudflare
帳號裡，風險可控；若要讓店員登入，建議照第 4 節開專用帳號。

**Organization access（重要）**

本站的 repo 屬於 `dongguang-medical` 組織，所以這一區要特別看：

- 該組織後面顯示 **Revoke**：代表**已經授權**，正常，不要按（按下去是撤銷）
- 顯示 **Request**：代表**尚未授權**，需要組織管理者核准，否則後台會連不到 repo
- 其他不相關的組織顯示 Request 可以忽略

**最下方的導向網址**

畫面底部會寫 `Authorizing will redirect to ...`，確認它是你自己的 Worker 網址。
這是防釣魚的檢查點，若出現陌生網域應立即取消。

## 4. 幫店員開通帳號

1. 幫店員申請一個 GitHub 帳號（或請店員自己註冊），記下帳號名稱
2. 到 repo 的 **Settings → Collaborators and teams → Add people**，
   輸入店員帳號，權限選 **Write**（需要能推送內容到 `main`）
3. 店員信箱會收到邀請信，請店員點信中的接受連結
4. 店員第一次登入後台時按 **Authorize** 即完成

> 若不想讓店員自行管理 GitHub 密碼，可由管理者代管一個專用帳號
> （例如 `dongguang-staff`），只把該帳號加入這個 repo，這樣 CMS 也碰不到
> 管理者個人的其他 repo。

## 5. 疑難排解

| 症狀 | 可能原因與處理 |
|---|---|
| 授權後跳錯或空白頁 | OAuth App 的 callback URL 沒填成 `<Worker網址>/callback` |
| 登入後看不到商品 | `config.yml` 的 `repo` 路徑不對，或組織授權顯示 Request 未核准 |
| 顯示 domain not allowed | `ALLOWED_DOMAINS` 與實際網域不符 |
| 本機開後台不需登入 | 正常，`local_backend: true` 會在 localhost 直接讀寫本機資料夾 |
| 儲存後網站沒更新 | 等 1 到 3 分鐘讓 GitHub Actions 重建與 Pages 發佈 |

## 6. 內容契約（與前台共用）

後台寫入的商品資料格式如下，前台建置流程需與此一致：

- 商品檔：`content/products/*.md`（YAML frontmatter + Markdown 內文）
- 品牌檔：`content/brands/*.md`，商品以 `brand` 欄位存品牌代碼指向它
- 新增商品的檔名：`YYYYMMDD-<短ID>.md`（slug 樣板 `{{year}}{{month}}{{day}}-{{uuid_short}}`，
  避免產生中文檔名）
- 圖片實體存放 `assets/uploads/`，frontmatter 引用路徑為 `/assets/uploads/...`

主要欄位：

| 欄位 | 說明 |
|---|---|
| `name` | 必填，商品名稱 |
| `taxonomy` | 必填，「主分類/子分類」單一字串，選項由 `scripts/data/taxonomy.tsv` 產生 |
| `price` | 純數字（例 `3500`），網站顯示時才加上 NT$ 與千分位；留空顯示「歡迎洽詢」 |
| `offering` | 複選：線上選購／門市洽詢 |
| `rentable` | 布林，開啟後出現在租賃專區 |
| `rental_price` | 字串，例 `800/月` |
| `shopee_url` | 勾選線上選購時填，商品頁會出現「到蝦皮下單」按鈕 |
| `subsidy` | 複選：長照2.0輔具補助／身障輔具補助 |
| `brand` | 品牌代碼，需對應 `content/brands/` 內的檔案 |
| `tags` | 標籤清單，例如「台灣製造」「保固一年」 |
| `specs` | 規格，label 與 value 成對 |
| `body` | frontmatter 之後的內文，即商品說明 |
| `images` | 圖片路徑清單，第一張為封面 |
| `published` | 布林，關閉即下架但保留資料 |
| `featured` | 布林，首頁「熱銷精選」 |

> 分類選項由 `scripts/data/taxonomy.tsv` 產生，**請勿直接手改 `config.yml`**。
> 新增子分類請改該檔案後執行 `python scripts/gen_cms_options.py`。

## 7. 其他備註

- **編輯預覽已關閉**（`editor.preview: false`）：本站沒有 CMS 預覽樣板，關閉以保持
  介面極簡。日後想開啟把該設定改為 `true` 即可
- **UI 語言**：Sveltia CMS 介面語言跟隨瀏覽器語言自動切換；所有欄位標籤與提示
  已在 `config.yml` 中設為繁體中文
- **數字欄位的上下鍵**：`admin/index.html` 內嵌了一段 CSS 隱藏 number 欄位的微調鍵，
  售價是直接鍵入的，點一下只加一元沒有意義，滑鼠滾輪經過還容易誤改
- **CDN**：`admin/index.html` 由 unpkg 載入 `@sveltia/cms` 最新版；如 unpkg 不穩，
  可改用 `https://cdn.jsdelivr.net/npm/@sveltia/cms/dist/sveltia-cms.js`
- **安全**：Client Secret 只存在 Cloudflare Worker 的加密環境變數中，絕不可寫進 repo
